02 Why kernels are hard

seL4 proved a whole kernel correct in 2009. Linux is about 4,000× larger and still unverified. Size is not the only reason.

seL4 — verified8,700 LOC
Linux — unverified≈36,000,000 LOC
vurl — this project[live] LOC

log scale · sources: seL4 SOSP'09, Linux Foundation 2023 report, ratchet.json

One line: what the ratchet means — verified coverage only increases between releases.
≈20 person-years for 8,700 lines of C. The proof is an order of magnitude larger than the code, and the ratio worsens with concurrency and driver state machines.
A proof binds one code version to one spec version. Linux merges changes hourly. This project pins spec commits and re-verifies against upstream Verus weekly.
Drivers are most of Linux's code and bugs, and talk to hardware nobody has formalized. Even seL4's theorem excludes boot code, assembly and hardware.
Shipped verification picks small stable targets: crypto, compilers, microkernels. Quark proved a browser kernel and ran untrusted WebKit tabs behind it. Same approach here.

Why this shape

  • A third-width pane is ~450–550 px. Four columns of prose cannot fit; stacked label/value fields can.
  • The list stays scannable (20 rows × 22 px); the detail gets the whole pane for one item.
  • Prev/next chips let an expert walk all 20 CVEs without returning to the list.
  • Same pattern for precedents, vjs steps, tradeoffs and proved modules — one interaction model everywhere.
  • Implementation: pane-local state swap, not a modal — keeps the three-pane context visible and avoids overlay stacking on mobile.

Inspect dock — a collapsible bottom pane, not a modal

Opened from the Built tab or its own header bar. Spans the full window under all three columns; the panes stay visible and keep their state. Collapsing returns it to a single bar. No overlay, no context switch.

Layout rules this redesign commits to

  • Density budget: at most three blocks above the fold per pane; everything else behind a tab, accordion or drill-in.
  • No table wider than two columns inside a pane. Multi-field records use stacked label/value in the drill-in.
  • Wide visuals only in the collapsible full-width bottom dock (proof DAG, architecture). Never squeezed into a column, never in a modal.
  • Code wraps with hanging indents; horizontal scroll is a bug, not a feature.
  • Chips and badges are nowrap; wrapping happens between chips, never inside one.
  • One accordion open at a time; the default open item is the most load-bearing one.
  • Tone is never color-only: every tone rail carries a text label in the drill-in and a legend in the list.
  • Live-data rule unchanged: every metric fetches from ratchet.json / stats.json; missing data renders an error and "not recorded".
  • iX components kept: IxVerusEditor (wrapped lines), IxPacketGrid (2-column CVE list), IxProofDag + IxBlind + IxToggle inside the new structure; pane layout keeps the #1302/#2904 fixes.
